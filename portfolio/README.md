The SQL in [examples.json](examples.json) was generated by the POC backend using the synthetic 100-table catalog on the Ampere A1 instance. The screenshots render those recorded responses in the actual PWA frontend. For repeatable capture, the local browser script simulates an authenticated portfolio session and replays the recorded API responses. It does not include an invite code, API key, or real banking data. The app drafts SQL; it does not execute these queries. Its displayed checks cover read-only SQL shape and table names. SQL syntax, column references, and business meaning remain marked as unverified in the UI.

## Regenerate

1. With the A1 backend, Elasticsearch, and model configuration running, run `portfolio/generate-examples.mjs` from the repository root. Set `POC_APP_DIR` if the app is in another directory, and `POC_OUTPUT` for the desired output path. The script resumes existing successful examples; remove or replace the output JSON to generate a fresh set. Keep model credentials in the local environment, never in this repository.
2. Install Playwright or set `PLAYWRIGHT_MODULE` to its installed module path. Install Chrome or set `CHROME_PATH` to its executable path.
3. Run `node portfolio/capture-screenshots.mjs` from the repository root. It starts the local app server, renders one recorded result per viewport, and writes ten PNGs plus [screenshots.json](screenshots.json).

Every example should be reviewed against the catalog again after regeneration. Model output can change between runs.
